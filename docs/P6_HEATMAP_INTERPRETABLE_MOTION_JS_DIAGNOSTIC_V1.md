# P6 heatmap可解释运动—local-JS诊断 v1

日期：2026-09-23。该实验在读取诊断输出前固定特征、source-disjoint五折、ridge alpha=100和
时间打乱负对照。只使用完整train fit已有的HRNet positive-mass统计与P6 local-JS target；全程
CPU，不读取reference、WER、utility、calibration、dev、test、held-out或policy replay。

## 目的与特征

旧KS/KO把31帧不确定性描述符整体压缩，没有显式计算相邻帧峰值/均值位置的运动。本诊断直接用
heatmap正质量分布的`mu_x/mu_y`，在当前offset0之前至多31个真实帧内，按body、face、left hand、
right hand分别计算8项运动：平均/标准差/P90/最大逐帧位移、最近一步位移、净位移、路径长度和
加速度。另保留每部位9项trace、entropy和probability peak的当前值、历史均值及变化，共32维
运动M与36维质量Q。视频开头不把重复填充计作零运动。

## Source-disjoint OOF结果

| 输入 | OOF R2 | Spearman | 相对K的R2变化 |
|---|---:|---:|---:|
| M（运动） | .01419 | .11774 | — |
| Q（质量） | .01869 | .13115 | — |
| M+Q | .02953 | .16539 | — |
| K/history | .25596 | .51638 | — |
| K+M | .26070 | .52118 | **+.00474** |
| K+Q | .26359 | .52389 | **+.00763** |
| K+M+Q | **.26820** | **.52799** | **+.01224** |
| K+M+M² | .26192 | .52254 | +.00595 |
| K+time-shuffled M | .25670 | .51685 | +.00074 |

K+M的五折R2均高于K；真实运动增量明显大于时间打乱运动，说明heatmap中存在较弱但真实的
时序信息。质量特征的增量比运动更大，二者联合最好。不过联合增量仍小于旧ordered-U相对K的
约+.0188，而且旧实验已经证明更高JS回归R2不保证更低WER，因此这里不能推导调度改善。

## 运动大小的形状

单变量相关总体较弱。最强的是右手最近一步位移（Spearman `.1064`），其次为身体最近一步
`.0972`、左手最近一步`.0777`和脸部最近一步`.0585`。右手最近位移的JS十分位均值从
`.0474`上升到中高区间约`.081--.083`，最高运动十分位略回落到`.0797`；脸部最近运动则在
中低区间达到峰值，最高十分位回落到`.0749`。长期净位移和路径长度大多呈更明显的中间高、
两端低形状。

这不支持“运动越大越重要”的单调规则。更接近数据的描述是：完全静止/视频起点的JS偏低，
近期出现适量运动通常对应更大的posterior变化，但极大或长期累计运动未必继续增加信息；部位间
形状也不同。第一十分位仍混有序列起点效应，因此这些曲线只能作描述，不能解释为运动的因果效应。

## 冻结结论

heatmap运动不是完全无用，但相对于decoder posterior history只是弱增量；运动与质量联合比单独
运动更合理。结果仅回答“heatmap里有没有与JS相关的时序信号”，不回答“能否降低WER”。该身份
明确为诊断，不能据此解锁闭环、calibration或held-out。证据位于
`Online/CSLR/results/phoenix-2014t_ISLR/p6_heatmap_interpretable_motion_js_diagnostic_v1_49faacc3/`。
