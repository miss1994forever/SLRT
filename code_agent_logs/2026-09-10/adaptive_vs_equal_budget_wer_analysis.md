# 自适应步长与等预算均匀采样 WER 接近的诊断

日期：2026-09-10

## 问题与结论

本报告只分析修复后 Phoenix-2014T dev 的既有结果，不重新运行模型、不读取 test、不修改算法。比较对象是相同 `span_weighted_15` 解码器下的：

- B2：均匀采样，目标平均步长 `1.482786...`；
- A0：由关键点运动因果决定步长 1--3。

结论是：**目前不能说 WER 天生对步长不敏感，也不能把接近主要归因于句子词数少。更直接的原因是 B2 与 A0 虽然 schedule 不相同，但窗口中心在时间轴上几乎总能相差不超过 1 帧；16 帧窗口和 15 帧 span 投票进一步平滑了这一微小位移。现有运动指标只按局部速度分配预算，没有证据表明它对准了真正影响识别的词边界或低可靠区间。**

A0 的确改变了不少句子的输出，但改善与恶化基本抵消：累计改善 48 个编辑错误，同时新增 43 个，净收益只有 5 个错误，即 `-0.133440` 个 WER 百分点。paired bootstrap 置信区间跨 0，不能宣称准确率提升。

## 逐样本配对分析

分析对 reference 和 hypothesis 使用统一评估器相同的 `clean_phoenix_2014_trans`，再用仓库 `wer_single` 逐句计算。

| 配对现象 | 样本数 | 占 519 句 |
|---|---:|---:|

## 句长是否是主因

| 清洗后参考句长 | 句数 | ref tokens | B2 WER | A0 WER | A0-B2 | A0胜 / B2胜 | 相同 hyp |
|---|---:|---:|---:|---:|---:|---:|---:|
| <=5 | 153 | 593 | 27.993% | 27.150% | -0.843 pp | 8 / 4 | 135 |
| 6--10 | 298 | 2,285 | 20.875% | 20.963% | +0.088 pp | 25 / 26 | 219 |
| 11--15 | 61 | 751 | 21.704% | 21.838% | +0.133 pp | 11 / 9 | 34 |
| >15 | 7 | 118 | 33.051% | 30.508% | -2.542 pp | 1 / 0 | 5 |

中位句长为 7，均值 7.22，范围 2--18。短句确实使“每句只变化一个词”时单句 WER 跳动较大；但聚合 WER 的分母是总参考词数，不是句数。6--15 词占 359/519 句和 3,036/3,747（81.0%）个参考词，在这个主体区间 A0 与 B2 仍几乎打平。因此“句子词汇少”不是总体接近的充分解释。`>15` 桶仅 7 句，虽然 A0 数值较好，却没有足够样本支撑长句更受益的结论。

从统计功效看，5 个净错误只相当于 `5/3747=0.133 pp`。当前按句重采样的 CI 约覆盖 -25 到 +16 个净错误的量级；519 个独立句簇和 3,747 个 token 尚不足以稳定辨别这么小的效应。增加长序列和边界密集样本比只增加大量容易短句更有信息量。

## 视频长度与自适应强度

按 metadata 的真实帧数分桶：

| 视频帧数 | 句数 | ref tokens | B2错误 | A0错误 | A0-B2 WER | A0胜 / B2胜 | A0/B2 clips |
|---|---:|---:|---:|---:|---:|---:|---:|
| <=80 | 146 | 604 | 145 | 144 | -0.166 pp | 6 / 5 | 6,017 / 5,513 |
| 81--120 | 191 | 1,312 | 271 | 267 | -0.305 pp | 18 / 14 | 13,075 / 13,100 |
| >120 | 182 | 1,831 | 429 | 429 | 0.000 pp | 21 / 20 | 18,523 / 19,093 |

长视频并未显示 A0 获得稳定优势；`>120` 帧恰好净零。短视频中 A0 因每句 16 帧 warmup 保守使用 stride 1，甚至可能比等预算 B2 使用更多 clips，这说明“全局等预算”不等于“每句等预算”。

A0 全 dev 的 stride 选择为：stride 1 `25,563` 次（67.96%）、stride 2 `5,597`（14.88%）、stride 3 `6,455`（17.16%）。其中每句至少 16 帧 warmup，合计最多 8,304 个 stride-1 决策可由 warmup直接解释，约占全部 stride-1 的 32.48%。A0 不是偶尔才自适应，但其预算重分配目前没有显示单调收益：按每句 stride-1 比例粗分组，低比例组反而 `+0.890 pp`，中比例组 `-0.140 pp`，高比例组 `-0.669 pp`；这是事后分桶且混杂句长/视频长度，只能说明没有简单的“越自适应越好”证据。

## 为什么不同 schedule 仍得到接近 WER

### 1. 窗口中心不同，但几乎总是邻近

逐样本比较 B2 与 A0 的 start 集合：

- 平均逐句 Jaccard 为 `0.530`，全局交并比为 `0.520`：精确中心只有约一半重合，说明 A0 确实改变了 schedule；
- 但对每个 A0 start 寻找最近 B2 start，平均距离仅 `0.314` 帧；
- 全部 37,615 个 A0 start 到最近 B2 start 的最大距离都是 **1 帧**。

因此两种策略不是在比较“关键边界附近窗口”与“远离关键边界窗口”，而主要是在比较同一局部的相同起点或相邻一帧起点。

### 2. 16 帧窗口使一帧偏移高度冗余

相邻 1 帧的两个 16 帧窗口共享 15/16 输入帧；即便相差 2 或 3 帧，也共享 14/16 或 13/16。S3D 的时空卷积/时间聚合会让相邻窗口表示具有相关性，这是架构上的合理推断；本轮没有抽取中间特征相似度，所以不能把它写成已测量事实。

### 3. span-weighted-15 再次平滑局部差异

B2 和 A0 都用同一个 `span_weighted_15`：每个中心对半径 7.5 帧内的窗口 softmax 概率做三角加权，再 argmax、去重和去 blank。由于 start 间隔仅 1--3 帧，一个词通常由多个高度重叠窗口共同投票。某个中心移动一帧或个别窗口类别变化，可能不会改变最终压缩后的 gloss 序列。这与 75.7% 样本最终 hypothesis 完全相同相符。

### 4. 当前信号是“运动量”，不是“边界/可靠性”

A0 使用置信关键点的归一化中位位移、因果 EMA 和最近 48 帧分位数：运动大取小步长，运动小取大步长；缺少可靠关键点时也保守取 stride 1。代码中没有词边界监督、模型熵、blank 转换、logit margin 或跨窗口预测不一致性。因此可以确认它**没有显式优化识别边界**；但“运动与词边界完全无关”尚未被直接测量，不能下此结论。

这解释了为何 A0 可以有效削减相对 stride-1 的计算量，却只比等预算均匀采样好 5 个错误：它控制了采样密度，但未证明把额外窗口放到了最有识别价值的位置。

## 对“WER 是否受步长影响很小”的回答

现有矩阵显示，在本模型、16 帧窗口、span-15 解码和 Phoenix dev 上，**从约 55.8k clips 降到 37.6k 时 WER 只变化约 0.2 pp；继续降到 28.0k/18.8k 时 WER 逐步升到 22.82%/22.93%**。所以在目前 1--3 的温和范围内，系统具有明显冗余，WER 对小的采样位置变化相对不敏感，但并非完全不受预算影响。

尤其不能外推到更快步长、不同窗口长度、边界密集序列、其他数据集或实时流式条件。本实验还把整段视频关键点预先用于生成因果 schedule（每次决策只看过去），但 decoder 的 span 投票和离线评估形式与真正逐帧低延迟部署仍有差异。

## 最小下一步实验（只用 dev）

按信息增益排序：

1. **schedule oracle / 压力测试，不训练模型。** 复用已保存的 stride-1 logits，构造多种中心子集：均匀、随机多种子、词 alignment 边界 oracle、预测变化点 oracle。在多个严格等预算层级（例如保留 67%、50%、33%）统一 span 解码。它能回答“预算放对位置最多能提高多少”和“当前数据是否存在可利用空间”。oracle 只用于上界分析，不能作为可部署方法。
2. **边界命中诊断。** 使用 dev alignment，测量 A0/B2 centers 到 gloss 边界的距离、边界附近采样密度和该处 logits 变化/错误，验证运动分数是否实际对齐边界。这一步直接检验目前缺失的因果链。
3. **可靠性/边界感知调度。** 在 dev 上加入仅依赖过去的 entropy、top-1 margin、blank/non-blank 转换、相邻窗口 JS divergence 等信号；冻结预算并与 B2 配对。参数选择和消融都只用 dev，test 不参与。
4. **长序列与边界密集预注册子集。** 按 metadata/alignment 在看预测前定义子集，报告配对错误和 bootstrap CI；不要根据 A0 获胜样本反向挑子集。
5. **扩大 dev 证据。** 若有合法训练/验证重划分，可做多个验证 fold 或跨数据集验证。最终方案和预算层级冻结后才运行 retrospective test，避免 test 泄漏。

首选第 1、2 项：可大量复用现有 logits，成本远低于完整 GPU 矩阵，而且最能判断“自适应策略没有空间”还是“运动信号没有把预算放对位置”。

## 证据与推断边界

直接证据包括：总体 WER/错误类型、逐样本胜负、句长/帧长分桶、stride 分布、start 集合距离、runtime 和 bootstrap CI。机制部分关于 16 帧重叠、span 投票的数学作用直接来自代码；关于 S3D 特征平滑是合理推断，尚未由特征相似度实验验证；关于运动信号没有与边界对齐，目前只能确认代码未显式使用边界，实际相关性需由下一步 alignment 诊断测量。
